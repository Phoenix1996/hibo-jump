# 海宝跳跳

一个无需安装依赖的浏览器图案归列游戏。项目使用原生 HTML、CSS 和 JavaScript，可直接由静态文件托管，也可通过 GitHub Pages 游玩。

## 开始游玩

[直接在线游玩](https://phoenix1996.github.io/hibo-jump/)。

直接打开 `index.html`，或从项目目录启动任意静态文件服务器。项目没有构建步骤，也不依赖第三方 JavaScript 包。

默认困难模式使用 7 种图案、8 列、每列容量 12、8 个暂存位、48 个问号和 3 个固定白格。开局列高固定为 6 列满格、1 列 11 格、1 列 1 格，共 84 个格位（白色固定格也计入格位）；各列的位置随机。可在设置中选择其他难度或自定义参数。新局生成过程显示进度；准备完成后，图块从左下到右上依次翻开。

## 玩法

- 列间移动时，顶部连续相同的图案会作为一组移动；目标列必须为空或顶部同图，并且要有足够空间。
- 暂存位一次存放一个图案。通关前必须清空暂存区，并揭开所有问号。
- 白色固定格不可移动，代表对应图案少了一格；它们不会被当作一种图案。
- 已完成的列会锁定。后退按钮撤销一步，重新开始会还原当前棋盘。
- 海洋、水果、宝可梦、宝可梦徽章和数码宝贝主题只改变图案外观。

困难棋盘直接按图案数量随机发牌，再用求解器检查可解性；检查包含顶部同图组、单个暂存、固定白格、问号揭晓和完成列锁定规则。每个主列至少混合 4 种真实图案，并保留至少 3 种可见图案；底层图案不出现三连及以上，每局最多 3 处相邻同图。48 个问号均匀分布到主列。生成器只接受有通关路径的候选，不会回退到完成底盘。搜索在 Web Worker 中运行，保持页面与加载动画流畅；直接打开 HTML 时可使用主线程的分段计算。简单、普通、自由自定义和前 10 个闯关关卡沿用反向打乱，第 11–30 关使用随机混排。

整组移动时，顶部图案依次错开出发，从源列顶部飞向目标列顶部再落入格子。各图案出发时分别播放音效，音高沿一组逐步上升，落地时触发支持设备的震动；一次整组操作仍计作一步、可一次撤销。

切换图片主题前会先加载和解码素材，避免慢网络下先显示空图。等待时主题按钮显示小转圈；加载失败或超过 8 秒时保留原主题，可以重试。已准备好的主题会复用素材。

## 关卡设计参考

[Decanta: Water Sort](https://github.com/alliterhorst/decanta-water-sort) 的关卡生成器采用随机候选局面并通过求解器验证可解性和难度。本项目借鉴这一流程，独立实现适合暂存位和问号规则的加权搜索与路径回放校验，没有复制其源码或素材。求解器用于确认有解，不承诺找到最短解。

## 开发核查

使用 Node.js 运行 `node scripts/verify-hard-levels.cjs 100`，检查随机列高、图案和问号分布，并通过游戏现有移动函数逐步回放求解路径到通关。`node scripts/verify-mode-levels.cjs` 检查全部 30 个闯关配置、预设和自定义边界，并检查后台线程与主线程的种子结果一致。`node scripts/verify-animation.cjs` 检查逐个出发的顺序、间隔、顶部路线和出发音高。

## 存档与离线游玩

游戏进度、三个存档、难度、主题和音效设置保存在当前浏览器的本地存储中，不会自动同步到其他设备。

每个存档保留最近 50 步撤销记录，刷新后仍可后退，问号状态和暂存内容会一并还原。当前页面里的完整撤销记录不受这个存档上限影响。旧存档没有撤销记录时仍可正常继续游戏。

闯关模式分别保存已通过关卡与解锁进度，包括第 30 关；全部通过后显示祝贺信息，可从关卡列表选择重玩。旧版只存解锁进度的记录会自动迁移。

第 1–10 关用反向打乱逐步入门，第 11–30 关使用随机混排和求解校验，避免增加打乱步数后仍保留长段同色。后段主列至少混合 4 种真实图案，底层最多二连、每局最多 3 处对子；列高为若干满列、一列少一格、一列一格，位置随机。已开始的旧局可以继续，尚未移动的旧后段关卡会迁移到新生成方式。

所有新局都会检查最终棋盘的可解性（包括问号和白格）。每种生成方式都需通过求解并回放校验；候选耗尽时提示重试，不交付未验证的棋盘。无暂存位模式的反向列间移动还要求可以按同色顶部规则还原。

切换难度、关卡、每日挑战或存档时，会等新棋盘生成成功后再提交状态。生成失败不会改变当前棋盘、规则、存档位置或撤销记录。

`board-generator.js` 统一各模式的生成流程，`level-generator.js` 提供困难候选及求解器，`level-worker.js` 在后台执行两者。所有模式均使用后台线程；不支持 Worker 或直接打开 HTML 时，采用页面线程上的分段计算。

在 iPhone 或 iPad 的 Safari 中打开游戏后，可使用“分享 → 添加到主屏幕”以网页 App 形式启动。首次联网打开后，服务工作线程会缓存游戏页面与主题图片，供离线游玩。

## 发布

推送到 `main` 分支会触发 `.github/workflows/pages.yml`，由 GitHub Actions 部署到 GitHub Pages。

发布前会检查 JavaScript 语法、100 个困难棋盘、全部闯关配置、移动音效和动画、主题加载、完成记录及生成失败恢复。`node scripts/verify-static-assets.cjs` 还会检查网页、后台线程、主题图片和离线缓存的资源路径与版本是否一致。任一检查失败都会停止本次部署。
