# 海宝跳跳

一个无需安装依赖的浏览器图案归列游戏。项目使用原生 HTML、CSS 和 JavaScript，可直接由静态文件托管，也可通过 GitHub Pages 游玩。

## 开始游玩

[直接在线游玩](https://phoenix1996.github.io/hibo-jump/)。

直接打开 `index.html`，或从项目目录启动任意静态文件服务器。项目没有构建步骤，也不依赖第三方 JavaScript 包。

默认困难模式使用 7 种图案、8 列、每列容量 12、8 个暂存位、48 个问号和 3 个固定白格。开局列高固定为 6 列满格、1 列 11 格、1 列 1 格，共 84 个格位（白色固定格也计入格位）；各列的位置随机。可在设置中选择其他难度或自定义参数。新局生成过程显示进度；准备完成后，图块从左下到右上依次翻开。

## 玩法

- 列间移动时，顶部连续相同的图案会作为一组移动；目标列必须为空或顶部同图，并且要有足够空间。
- 暂存位一次存放一个图案。通关前必须清空暂存区，并揭开所有问号。
- 白色固定格不可移动，代表对应图案少了一格；它们不会被当作一种图案。
- 已完成的列会锁定。后退按钮撤销一步，重新开始会还原当前棋盘。
- 海洋、水果、宝可梦、宝可梦徽章和数码宝贝主题只改变图案外观。

困难棋盘直接按图案数量随机发牌，再用求解器检查可解性；检查包含顶部同图组、单个暂存、固定白格、问号揭晓和完成列锁定规则。每个主列至少混合 4 种真实图案，并保留至少 3 种可见图案；底层图案不出现三连及以上，每局最多 3 处相邻同图。48 个问号均匀分布到主列。生成器只接受有通关路径的候选，不会回退到完成底盘。搜索在 Web Worker 中运行，保持页面与加载动画流畅；直接打开 HTML 时可使用主线程的分段计算。简单、普通和自定义模式沿用反向打乱。

整组移动时，顶部图案依次错开出发，从源列顶部飞向目标列顶部再落入格子。各图案出发时分别播放音效，音高沿一组逐步上升，落地时触发支持设备的震动；一次整组操作仍计作一步、可一次撤销。

## 关卡设计参考

[Decanta: Water Sort](https://github.com/alliterhorst/decanta-water-sort) 的关卡生成器采用随机候选局面并通过求解器验证可解性和难度。本项目借鉴这一流程，独立实现适合暂存位和问号规则的加权搜索与路径回放校验，没有复制其源码或素材。求解器用于确认有解，不承诺找到最短解。

## 开发核查

使用 Node.js 运行 `node scripts/verify-hard-levels.cjs 100`，检查随机列高、图案和问号分布，并通过游戏现有移动函数逐步回放求解路径到通关。`node scripts/verify-animation.cjs` 检查逐个出发的顺序、间隔、顶部路线和落地音高。

## 存档与离线游玩

游戏进度、三个存档、难度、主题和音效设置保存在当前浏览器的本地存储中，不会自动同步到其他设备。

在 iPhone 或 iPad 的 Safari 中打开游戏后，可使用“分享 → 添加到主屏幕”以网页 App 形式启动。首次联网打开后，服务工作线程会缓存游戏页面与主题图片，供离线游玩。

## 发布

推送到 `main` 分支会触发 `.github/workflows/pages.yml`，由 GitHub Actions 部署到 GitHub Pages。
