# 海宝跳跳

一个无需安装依赖的浏览器图案归列游戏。项目使用原生 HTML、CSS 和 JavaScript，可直接由静态文件托管，也可通过 GitHub Pages 游玩。

## 开始游玩

直接打开 `index.html`，或从项目目录启动任意静态文件服务器。项目没有构建步骤，也不依赖第三方 JavaScript 包。

默认困难模式使用 7 种图案、8 列、每列容量 12、8 个暂存位、2400 步反向打乱、48 个问号和 3 个固定白格。开局列高固定为 6 列满格、1 列 11 格，备用列放 1 个图案，共 84 个格位（白色固定格也计入格位）。可在设置中选择其他难度或自定义参数。新局生成过程显示实际进度；准备完成后，图块从左下到右上依次翻开。

## 玩法

- 列间移动时，顶部连续相同的图案会作为一组移动；目标列必须为空或顶部同图，并且要有足够空间。
- 暂存位一次存放一个图案。通关前必须清空暂存区，并揭开所有问号。
- 白色固定格不可移动，代表对应图案少了一格；它们不会被当作一种图案。
- 已完成的列会锁定。后退按钮撤销一步，重新开始会还原当前棋盘。
- 海洋、水果、宝可梦、宝可梦徽章和数码宝贝主题只改变图案外观。

困难棋盘从完成状态反向生成，并比较多个候选局面；列高整理通过单图案暂存移动完成。生成器优先保留打乱步数较多、避免三连及以上、相邻同图较少且已完成列不超过一列的局面；如果候选局不够打乱，会提示重试，不会退回只移动一个图案的近乎完成棋盘。问号会优先盖住相邻重复图案，减少开局一眼可见的对子。

## 关卡设计参考

[Decanta: Water Sort](https://github.com/alliterhorst/decanta-water-sort) 的关卡生成器采用随机候选局面并通过求解器验证可解性和难度。本项目借鉴了候选评估与关卡组织思路，没有复制其源码或素材；当前棋盘仍由本项目自己的反向打乱生成。

## 存档与离线游玩

游戏进度、三个存档、难度、主题和音效设置保存在当前浏览器的本地存储中，不会自动同步到其他设备。

在 iPhone 或 iPad 的 Safari 中打开游戏后，可使用“分享 → 添加到主屏幕”以网页 App 形式启动。首次联网打开后，服务工作线程会缓存游戏页面与主题图片，供离线游玩。
